# Multi-agent collaboration & communication — design principles for our swarm (S14 deep-research)

Goal: DHH-grade, transferable PRINCIPLES for how multiple agents COLLABORATE and COMMUNICATE — to improve or validate our architecture, the foundation of everything. Focus is collab/comms + best practices, not general orchestration. Sources: `blog.lightnote.com.cn/32-ai-orchestrators-benchmark-7-dimensions` + repos/READMEs via `gh` + FOUR source-level deep-dives (Omnigent, Orca, Paseo, ccswarm+Hermes) saved under `docs/research/_deep/` (1335 lines, every claim cites a file we read).

## Architecture spine (the frame every principle hangs on)
The swarm IS a distributed system: sessions (Claude/Codex, possibly cross-machine via AGENTHOP_TEAM) are nodes that share NOTHING and talk only by message. Orchestration is a distributed SCHEDULER over a replicated log — an OS atop that hardware, not a controller with a global view.
- **Spine rule — no component assumes a global, current, consistent view; it acts on the log and re-validates at the CAS commit.** Orchestration schedules; it does not control. (Our control-log = the replicated log; board-admission re-admit-on-current-CONTROL = TOCTOU-safe commit.)
- **Three layers, and the defend/borrow line follows them:** INFRA/hardware = the bus (transport only, zero policy) ⇒ DEFEND; OS/kernel = scheduler + admission + liveness ⇒ ours, harden; APP/policy = collaboration strategy (review, fan-out, human-routing, learning) ⇒ BORROW here, never below.
- **Mechanism vs policy separation:** the bus API is our ISA; don't rev an ISA casually. Every borrowed strategy sits ABOVE the bus so policy churn never reaches transport. That is how upfront extraction prevents rework — policy changes stay in the app layer.

## INFRA layer — DEFEND (our bus already leads the UI-centric heads)
- **C1 — agents message + HAND OFF work directly, not only through a human hub.** [KEEP — edge] · our bus does agent↔agent messaging + handoff (git-snapshot transfer) + durable inboxes; Paseo's cross-agent messaging is in-daemon turn-injection, single-daemon only, and its relay is best-effort client↔daemon with no durable mailbox. · we win cross-machine + cross-process durable delivery — defend, don't regress to a hub-only model.
- **C4 — shared durable state is the comms medium; chat is ephemeral.** [KEEP — edge] · control-log (CAS) + board + projection + PROGRESS = file-is-authority (S18); a collaboration CONCLUSION lands as an on-disk artifact, not a message. · never let a decision live only in chat.
- **C7 — communication discipline is architecture: budget messages, stay silent in-transit, route by layer.** [KEEP — edge] · S26-S29/R21 (1 task = 2 messages; silent in-transit = durable delivery is the receipt; same-family native vs cross-family bus; coordinator gets only dispatch/delivery/blocker). Omnigent INDEPENDENTLY reaches the same rules (inbox-not-poll; 「act in the same turn you announce」; a spawn-count fan-out cap) — convergent evidence this is right. · codify it as the swarm's comms contract.
- **C8 — address a STABLE, UNFORGEABLE identity, not a drifting handle.** [KEEP + UPGRADE] · our F40: a codex handle drifts on restart to a dead inbox. Paseo mints a daemon-side randomUUID persisted independent of the provider thread ID — restart swaps a fresh thread under the SAME ID (`agent-manager.ts:760`); Hermes makes the handle `HMAC(id|parent|created_at)`, verified on every call, with a child's tools forced to a SUBSET of the parent's (`subagent_lifecycle.py`). · upgrade: seat = a minted UUID (the thread ID becomes a swappable field) + a capability HMAC. · pitfall prevented: handle-drift dead-letters AND permission-laundering (R16) — both closed in code, not convention.
- **C9 — receipts + at-least-once + IDEMPOTENT delivery: a dropped or doubled message is a defect, not noise.** [KEEP — edge] · durable inboxes, claim = atomic rename (idempotent), failed escalation retried (sentinel LS4), dead-letter watch raises routing incidents. · exactly-once is impossible in a distributed system; at-least-once + idempotency is the correct answer — keep.

## OS layer — scheduler, admission, liveness (ours; harden)
- **C10 — coordinate by PULL-claim, not push to a bottleneck; grant authority at claim-time; re-validate on current state.** [KEEP — edge] · board-admission pull + re-admit on current CONTROL = a work-stealing scheduler with no central dispatcher (no SPOF, TOCTOU-safe). · our strongest coordination principle — defend.
- **C5 — bind a pipeline STAGE to a ROLE; not every agent does everything.** [BORROW/formalize, MED] · ccswarm plan→quorum→implement→review→fix; Omnigent supervisor→typed sub-agents; our TaskSpec.roleProfile EXISTS but dispatch ignores it. · wire role+stage into board-admission so a node tagged role=review only admits a reviewer-profile claimant. · rework prevented: a wrong-role agent half-does a node and it must be reopened.
- **C11 — 「done」 is an OBJECTIVE, evidenced verdict bound to the head SHA, never a self-report.** [BORROW, HIGH] · Omnigent: a per-finding `{key, status, reason(evidenced)}` receipt invalidated by any sha256 change, two reviewers proving completion on the exact head SHA (`review_cycle.py`, 「a passing review is coverage, not correctness」); ccswarm: a machine-parseable SANGHA_DECISION tally; Orca: outcome fuses 6 facets with a trust order so a worker that claims 「done」 on a clean git projects `finished_unverified` (`attempt-outcome-projection.ts`). · make 「declared gate green + evidence」 the admission precondition; never trust self-reported done. · pitfall prevented: 「looked done, gate was red」 ⇒ reopening a closed node.

## APP layer — collaboration POLICY (borrow here)
- **C2 — review by DIVERSITY + INDEPENDENCE: a different-family reviewer, handed only the diff, not the author's reasoning.** [BORROW, HIGHEST] · Omnigent routes each diff to a different VENDOR, handed an immutable OUT-OF-WORKTREE diff snapshot + the acceptance contract — never the author's worktree or transcript — and escalates to a human if under two vendors are available (`cross-review/SKILL.md`); ccswarm requires a role-distinct quorum. · our decision-batch is single-reviewer (shared blind spots) and over-shares context with the reviewer. · route the verify pass to a different model-family AND hide the author's reasoning; a CONFIRMED finding needs one cross-family second. · pitfall prevented: an author-model blind-spot bug that a same-family reviewer rubber-stamps ⇒ a post-merge revert. · right-size: this is cross-vendor + information-hiding + a machine verdict, NOT a consensus algorithm.
- **C3 — parallel attempts need WORKTREE ISOLATION + an evidence-picked winner; the AUTO winner-picker is greenfield — LEAD, don't borrow.** [LEAD] · no deep-dived head automates it (Orca is manual, Omnigent has no engine) — the field's open GAP. · we already have the exact substrate: race K attempts in isolated worktrees, commit via the CAS log so exactly ONE wins and the losers are fenced (the distributed spine), pick by C11 evidence. · acceptance: a K=2 node admits the passing attempt and fences the other (single-active preserved). · pitfall prevented: split-brain / duplicate winners — avoided BY the CAS commit, not by hope.
- **C6 — the human is a first-class collaborator: a durable decision-GATE whose resolution is INJECTED into the worker's next turn.** [BORROW, HIGH] · Orca: a worker opens a gate ⇒ task `blocked`; the coordinator NEVER auto-resolves (humans do, desktop or mobile); on resolve ⇒ `ready` and a `--- DECISION GATE RESOLVED ---` block is appended to the next dispatch preamble so the answer physically re-enters the agent's context (`decision-gate-store.ts` + `coordinator-task-dispatch.ts`). · our sentinel DETECTS blocked but only emits coordinator text — no needs-you lane, no inject-back (its open ③ gap). · feed sentinel events to a projection 「needs-you」 lane; the S19 approval carries a reply handle; an authorized dispatcher injects the resolution into the next turn. · 「the coordinator never auto-resolves, humans do」 = our R16 living in their code. · pitfall prevented: a stranded blocked agent silently idling to timeout.
- **C12 — collaboration improves itself with a CHEAP procedural loop, not ML.** [BORROW, now concrete] · Hermes = 3 cheap pieces: an outcome ledger (`.usage.json`) ⇒ an idle-gated curator that ages active→stale→archived and consolidates ⇒ the surviving skills' ≤60-char descriptions ARE the routing surface the system-prompt index reads (`curator.py`, `skill_usage.py`). · our dispatch is static (roleProfile ignored, no outcome memory). · record per-node pass/fail + reviewer-find-rate into the projection; bias future role/model routing toward what has passed. · right-size: this is procedural-memory curation, NOT reward/model training (DSPy+GEPA lives in a separate repo). · pitfall prevented: re-dispatching a node-type to a model that keeps failing it.
- **C13 — a joiner or escalation inherits a task-scoped WORKING-SET, not the full history.** [KEEP/extend] · Traycer scopes a shared context a mid-task agent reads to catch up; our handoff already attaches summary + git snapshot; Paseo wraps injected turns in a `<paseo-system>` envelope that marks injected vs human. · extend to the C6 inject-back path: a needs-you escalation ships the scoped working-set (screen + block cause) + the envelope tag, not a firehose. · acceptance: a mid-task escalation is actionable from its payload alone.
- **C14 — two comms RAILS: an inner capability-budgeted tool-RPC rail, separate from the outer agent↔agent rail.** [BORROW, novel-to-us] · Hermes: a sandbox script calls host tools over a token-auth UDS/TCP channel (token ⇒ allow-list ⇒ call-budget ⇒ dispatch, `code_execution_rpc.py`), kept distinct from inter-agent messaging. · we have the outer rail (the bus); the inner intra-node tool rail is unbuilt. · maps onto the spine: inner = intra-node tool calls, outer = inter-node agent messages — keep them separate so a tool-call budget never rides the agent bus. · pitfall prevented: an unbudgeted tool loop starving the message rail.

## Verdict — leverage-ranked (to be BEST at orchestrating the swarm)
Defend the INFRA (C1/C4/C7/C8/C9/C10): our bus + durable inbox + control-log + comms protocol already lead the UI-centric heads; the one infra change worth making is C8 (minted-UUID seat + capability HMAC) — it closes F40 AND R16 in code.

Borrow at the APP layer, in this order:

1. **C2** cross-family + information-hiding review — catch author blind spots (highest leverage; prevents the revert).
2. **C11** evidenced done bound to the head SHA — make 「done」 mean gate-green, never self-report.
3. **C6** decision-gate inject-back — never strand a human decision.
4. **C5 then C3** role→stage binding, then race-the-uncertain-nodes via the CAS log (C3 is where we can LEAD the field, not follow it).
5. **C12** a cheap procedural learning loop — let the swarm learn what passed.
6. **C14** an inner tool-RPC rail — isolate tool budget from the agent bus.

The meta-lesson (CM): everyone's glamorous consensus/fan-out is unbuilt; our edge is that we ALREADY have the boring correct substrate (a CAS log + a durable cross-machine bus) that the real mechanisms need. Build the infra; the 「magic」 is ours to actually ship.
