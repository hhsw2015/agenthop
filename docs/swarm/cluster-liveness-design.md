## 0. 北极星场景(user 终极定调 2026-10-04,本设计的验收顶层)

**「晚上交代,早上验收」**:user 给目标 → 一轮设计确认(R4 的 design 节点,这是唯一需要 user 深度参与的环节)→ user 去睡 → 集群整夜自转(实现/审查/返工/改派/升级全自治)→ 次日 user 醒来只做验收。中途打扰 user 的唯一合法理由 = 三类裁决里**真正紧急**的(花钱超票据/不可逆且等不到天亮);其余一切 approval-wait 挂着等天亮,挂着 ≠ 停摆(停摆定理第②合法静默形态)。

**自循环判据(user 终定调,本设计的总验收)**:集群进入自循环 = 推进的每一环都由集群内部驱动——以省时为目标,角色做适配的事,主动认领、完成、汇报,共同推进总进度,持续运转,且踩过的坑自动长出免疫。**检验法:数「外部激活」次数**——user 或协调者人肉推一把才动的每一次,都是自循环的一个漏洞,都要能指出「哪条机制本该接住它」。自循环跑通的那一刻,人从循环里抽离,只剩给目标与验收——这就是数字员工存在的价值;反面(每个成员都要人激活一下才动)就是今晚反复付学费的形态。

本设计的所有机制都是为这个场景服务的,对账关系:
- 「集群整夜自转」⇐ INV-1 非空性 + sweep(§1):任何时刻都有人干活或有武装等待;
- 「不打扰」⇐ R3 自主默认 + R3-b 问询带默认 + approval-wait 的 awaiting-human 形态(§5/契约):问题自己消化,消化不了的挂起不拦路;
- 「出事不静默」⇐ 监管链 INV-2 + 心跳分层(§2/§3):断链几十秒内被机器发现并自愈或留痕;
- 「醒来可验收」⇐ 完成证据耐久(F13)+ 投影/报告落盘(§2c):早上看的是证据不是转述;
- 「第二晚更顺」⇐ 免疫流水线(§4):昨晚踩的坑今晚有回归测试守着。

**承诺的诚实限定 [R2-P3-1]**:非空性保证「不停摆」,不保证「次日必完成」(进度由任务量定);非紧急审批挂起仍阻塞其依赖链(这是语义不是缺陷);「最坏一个 tick」只约束检测与发起,成员响应/投递/admission 另有时延;「零介入」验收同时核成果与未决原因,真紧急裁决的正确唤醒不算失败。

**今晚就是这个场景的第一次不合格演练**:user 三次被迫醒来介入(F21 停摆/批准询问/门槛纠偏)。每次介入都已转化为本设计的一条机制——验收标准:同样复杂度的任务,下一次整夜零介入。

## 0b. 协调者/观测者是常设角色,不是脚手架(user 定调 2026-10-04)

人从循环抽离 ≠ 组织不要项目经理。**协调者(推进整体进度、裁定、派发判断类决策)与观测者(全局进度可见、停摆检测)是组织的常设角色**——自循环消灭的是「人肉充当这两个角色」,不是角色本身。分工定格:
- **机械面归代码**:sweep(到期处置/改派/催办)、INV-1 校验器(停摆检测)、投影+看板(观测数据面)——这些是两个角色的「自动化下属」。
- **判断面归协调者 Dot**(本会话这类长驻会话):契约裁定、审查组织、范围决策、F 处置定性、user 门物料——不可机械化的部分,但它自己也在 sweep 的监督下(patrol-pulse wait:协调者迟钝同样被催,F22 教训)。**协调者的 ping 纪律与成员对偶 [user 定调 2026-10-04]**:任何入站信号(sweep 催办/成员报备/产物落盘)对协调者都是**全局再调度的触发令**——收到即跑调度循环:①消费新产物;②扫全集群(谁闲/谁忙/板上何事无主);③找新的可并行边(无依赖/无域冲突/不抢稀缺资源)派发或上板;④处理信号本身。成员收 ping 问「我该不该领活」,协调者收任何消息问「全局还有什么该动而没动」——角色的定义性差别。**⑤ 调度循环的收尾强制步 [F23+D2]:逐成员处置清点,且机器兜底与适配提示分开**——R8 只覆盖「idle×有适配条目」;另设**无处置检查**(idle 且缺当前有效处置记录 ⇒ 开协调者待办,不管板上有没有适配活;处置记录带成员+观察切面关联与更新条件,旧理由不永久覆盖新一轮空闲);该兜底交付前,F23 的机制化宣称按「纪律+部分机器」如实标注。原文:——调度完成的定义不是「每个任务有 owner」,是「每个成员有去向」:再扫一遍成员状态,每个 idle 成员必须有显式处置之一:a) 派单/上板适配活;b) 依赖门拆无争议子集先行放行;c) 书面声明「合法空闲+理由」(如审查员两单间隙)。**没有书面处置的 idle 成员 = 本轮调度未完成**。F23 根因:协调者数「轨道都有人」却不数「人都有轨道」——任务视角与成员视角的清点是两回事,负载均衡按后者算。机制归宿:本步进协调者循环(纪律)+L2 的 R8-idle 规则(机器兜底:漏点的成员会被 sweep 挂到协调者脸上)+心跳/投影按成员维度记 idle 时长(观测面:空闲时长可见即可审计)。
- **观测面产品归 viz**:人类/协调者看同一块板(PROGRESS→正式投影),观测者角色的交付物就是这块板。
与北极星的关系:user 抽离后,协调者 Dot 就是「代理项目经理」,它持续推进、只在三类裁决敲 user——组织始终有人(Dot)负总责,这正是「持续推进整体项目进度」的承接。协调者自身的可用性受 §3 心跳分层监督(它也是被看守者)。

## 2b. 双端监管(INV-2b,rev2 增补;F22 实证 + round-1 审查 P1「证据消费链」的回应)

**问题形态(F22,2026-10-04 上午)**:报告按时落盘、生产者转入合法待命、wait 却已被生产者的完成关闭——「产物躺在盘上没人消费」对一切监督不可见。user 从看板上无法区分「交接瞬间」与「断链」。

**根治:监管链覆盖交接的两端。** INV-2 只保证「有人负责做」;INV-2b 补「有人负责收」:
- a. **生产与消费是两条 wait,各走合法转换 [R2-P1-2 重写:生产完成绝不冒用 action_done]**:信封开**生产 wait**(owner=受派生产者);生产者完成=以完成事实 close 生产 wait(resolution 引用产物 locator+requestId),**同一原子批**开**消费 wait**(owner=消费者/验收者,deadline=消费窗口,由 tick 周期派生)。消费者验收并同批登记下游 intent(或合法终局——最终叶节点允许无下一棒)后 close 消费 wait。timeout 的 action_done 只属于催办动作确认,业务报告永不塞进它(advanceWait 本就拒绝 open 态 action_done——审查方实测,该守卫是特性);催办 notice 在途时生产完成 ⇒ 生产 close 照走,晚到的 notice 确认按既有 late-confirm 规则拒。产物未消费 ⇒ 消费 wait 到期 ⇒ sweep 催消费者。
- b. [新] **产物目录是被看守的源**:dispatcher tick 扫描约定产物目录的新文件 vs 消费记录;「新产物且 T 内无消费转换」⇒ 自动开 repair-wait(owner=应消费者)。a 的兜底:忘走 wait 的交接,落盘本身触发监督。
- c. **交接瞬间可见**:投影暴露每个产物的 produced→consumed 时间差;viz 渲染「已出 N 分钟未消费」——user 不用猜。

强制点:a=[新] 两条 wait 的原子 close+open(生产 close 与消费 open 同批,见 2b-a 正文;非 action_done 复用 [D3 更正]);b=[新] dispatcher tick 一个扫描步;c=[新] 投影加字段(不升版)。

## 2c. 期限不是进度模型(rev2 增补,user 定调 2026-10-04):deadline 只用于「死了没」,不用于「快了没」

**问题**:协调者的工时估算系统性不准(实证:今晚 ack 自报 25-75 分钟的单,实际 10 分钟到 4 小时都有;「90 分钟封顶」的估算既造成过早催促的风险,也造成 F22 那种「估算太长 ⇒ 监督窗口太松」)。**用估算驱动设计 = 把一个已知不可靠的信号焊进机制。**

**原则:事件驱动为主,期限只做死亡兜底。**
- a. **一切「下一棒」由事件触发,不由期限触发**:产物落盘(INV-2b 的 b:目录扫描)、完成转换提交、消息到达——这些是真实信号,到了就走,不等任何估算的钟。期限的唯一职责是「信号迟迟不来时判定可能死了」。
- b. **两类时钟分开 [R2-P1-4 重写]**:**语义期限**(retryAt 的重新就绪、validation-wait 的验收停留上限、问询默认的决断时刻、物理证据窗)是业务约定,**任何健康证据都不得顺延它们**——owner 再活跃,T 到了默认照用、验收照停、重试照放行。**探活/催办时刻**(「该去核查 owner 死活了」)才接受证据续期:续期证据必须是**匹配 subject 的推进证据**(该单的 commit/该 wait 的状态转换,不是 owner 的无关活动),重复证据 no-op,续期有操作记录与上界(A1 获批则走其 episode 额度,不另开免费续期口)。初始值取粗量级,到期动作=探活再决定,不定罪。
- c. **估算不进契约字段**:ETA 是 owner 的自报信息(礼貌、可观测),写进消息与备注;机制字段(deadlineSec)只装兜底量级。禁止把「我觉得他要 90 分钟」写成任何会触发动作的阈值。
- d. **消费窗口同理**(修正 2b-a 的「如 15 分钟」):那是量级示例不是设计参数;真实参数 = 「一个 dispatcher tick + 缓冲」,由 tick 周期派生,不由人估。

强制点:a=[已有](sweep 事件消费+目录扫描进 2b);b=[接线](探活续期:仅限可延期种类、须匹配 subject 的推进证据,见 2c-b 正文 [D3 更正]);c=[纪律+模板](派单模板的 deadline 字段写量级表取值,不写自由估算);d=[定义修正]。

## 2d. 拉式领活(rev2 增补,user 定调 2026-10-04):空闲成员主动领任务,任何外部力量(user/协调者)都不是风箱

**问题**:当前一切任务靠协调者推(push)——协调者迟钝/掉线,空闲成员就坐着;user 不得不来吹火。这违反 Dot 定位:数字员工做完活该**自己去看板找下一件**,不是等派。

**机制(三件,全部复用已冻结零件)**:
- a. **耐久活板(work board)**:无主活以可认领条目存在于耐久位置(v1=~/.agenthop/swarm/board/<itemId>.json,含 spec 摘要/适配域/优先级;与 brain 的 readyTasks 同构——DAG 对 ephemeral worker 本就是拉式板,本条把同一语义给 durable 成员)。协调者的职责从「派活」收缩为「上板」(curate),上板即卸责(board 条目自带监督:认领期限+无人领→sweep 升级)。
- b. **认领=申请,执行权唯一来自 dispatcher admission [R2-P1-3 重写]**:板条目的原子改名只是**预留申请**(防两人同时填表),不是执行授权。申请被 dispatcher 下一 tick 消费:在**当前 CONTROL** 上跑既有 admission(spec/输入在当前版、依赖 accepted、节点级单活、预算/容量、授权)→ 通过则原子提交 intent+binding+信封 wait 并回 receipt(写申请者 inbox+板条目标 granted),**拿到 receipt 才开工**;拒绝则板条目标 rejected+理由。两个条目指同一 node ⇒ admission 的节点单活挡第二个;文件预留后 CONTROL 提交失败/崩溃 ⇒ 预留是无权力的孤文件,dispatcher 重放时按申请重审或过期清除——跨存储原子性不被假设,board 是申请队列与事实投影,**绝不是第二执行账本**(冻结 team 的 claim/lease 边界不被触碰,Stage B 另审立场保留)。远端成员的申请通道=同一 dispatcher 的收件面,不同主机 ~/.agenthop 不默认同一板。
- c. **sweep 补一条 R8-idle 规则**(即此前延期的第五规则,现在有了明确形态):检测「成员 idle × 板上有其适配域的未领条目」⇒ ping **成员本人**(不是协调者):「板上有适合你的活」。成员收 ping 后自己决定领不领(决策权在成员,sweep 只是闹钟)。**这样脉搏来自集群自身的心跳(sweep),领活决策来自成员自身——user 和协调者都退出风箱角色。**
- 成员侧义务(行为契约增条,随本设计送审;user 两次定调 2026-10-04):**完成即三连——报结果、看板、报去向**。完成报告的末行必须是可用性声明,三选一:「已认领板上 X」/「板上无适配活,转 idle 待命(fitProfile=…)」/「仍有在途单 Y,继续」。**转入 idle 的那一刻就是向协调者报到的那一刻**——让协调者手里积压的可并行活第一时间配对出去(idle 报到=协调者的配对触发事件,push 侧;与 sweep R8-idle 的周期检测,pull 侧兜底,双向夹住空档)。idle 报到消息极短(一行),成本≈0,换来的是配对延迟从「下个 sweep tick」降到「完成瞬间」。
- **ping 的接收纪律 [user 补定调 2026-10-04]:成员自判状态,忙则忽略**。sweep 的 idle-ping 是提示不是指令——收到的成员先自查:手上有在途单(binding/claimed 未完)⇒ **忽略 ping,不回不中断**(sweep 按 roster 的 idle 信号发 ping,信号可能滞后或误报,成员的自我状态判断优先于外部信号——F17 同源:外部信号不定罪,本人现场最权威);确实空闲 ⇒ 看板走认领流程。误 ping 不需要道歉回执,静默忽略即是正确处理(减少消息噪音,R1)。
- **认领的两档纪律 [user 定调 2026-10-04 + R3 对齐]**:看板后分两档:
  - **普通条目(默认):领即报备,非先批后领**——fit+依赖清就直接 CAS 认领,认领消息**立即**发协调者(报备);协调者有一个 veto 窗(一个巡检周期,发现误领可改派)。理由:先批后领让每次认领都等协调者在线,协调者恰是今天两次事故的瓶颈(F22);CAS+fitProfile+dependsOn 已防双领误领,报备+veto 兜剩余风险。这就是 R3 两层判据的认领版:可撤(改派便宜)⇒自主+报备。
  - **标记 requiresApproval 的条目(设计/冻结/合并面/花钱):先批后领**——板条目带该标记,认领请求发**协调者角色**(协调者 Dot,§0b 的代理项目经理;不是人),批了才领。难撤⇒审批,同样是 R3。**人只出现在三类裁决**(改原则/花钱超票据/不可逆):requiresApproval 条目若同时触碰三类,协调者 Dot 把它升级为 approval-wait 等人,其余一律协调者 Dot 自批——审批层级:成员自主 < 协调者批 < 人批,逐级只升必要的。[user 澄清 2026-10-04:批=协调者角色,人从循环抽离]
  目标同 user 定调:集群不大面积空闲(ping 到即看板),且不把协调者变成每次认领的同步点。
- 诚实边界:成员是 harness 会话,无输入不会自发轮询——所以 c 的 sweep ping 是机制底座(把「看板」变成会被敲门的义务),成员侧的「完成即看板」靠行为契约+ping 兜底。两层合起来:最坏情况=一个 sweep tick 的延迟,而不是「等 user 发现」。

强制点:a=[新,薄](目录+条目 schema);b=[接线](单飞锁同款原子操作);c=[接线](sweep 第五规则,roster idle 信号已有);成员义务=[契约](行为契约 12 条增补第 13 条)。

## 3. 心跳分层(「谁看守看守者」的诚实答案)

- L0 [已有] sweep/dispatcher:第一看守,盯全部 wait。
- L1 [接线] **分环心跳 [R1-P1-4 重写]**:单文件多字段 JSON {pass:{lastTickSec,inFlight,mode}, sweep:{lastTickSec,inFlight,mode}, instance, pid}——**每环独立记录**,一环健康绝不掩盖另一环停摆(pass 活 sweep 死 ⇒ sweep.lastTickSec 陈旧可见,反之亦然)。inFlight(在途步骤+起始时刻)让「长 IO 中」与「挂死」可区分:超过该操作类的期限预算 ⇒ suspected 非死。
- L2 [新,薄] **看守对 [R1-P2-2 收权]**:独立时钟的第二进程(v1=协调者 harness 唤醒;其周期与启用状态在 PROGRESS 声明,未满足时不宣称覆盖)读 L1 分环字段。陈旧 ⇒ **只做三件事**:① 写耐久事故记录(不依赖 L0 的 CONTROL 写手——直接文件,独立于失效环);② 有预授权票据的恢复动作照票执行(旧实例确认退出/fencing 后才起新实例,**绝不因心跳旧偷单活锁**);③ 无票据 ⇒ 通知人(耐久+总线双通道)。多看守者竞争安全**不在已验范围**(锁欠条措辞保持,不扩写)。
- 边界声明:L2 死 + L0 死同时 = 双重故障,v1 接受(部署前提),记欠条。**L0 任一环死从「静默」变为「分环心跳陈旧可检测」——停摆从不可见变为可见。**
