# 协调者控制台(S21 简报,user 定调 2026-10-05:语音+聊天界面=蜂群的前端)

user 原话要义:语音助手该有一个 ChatGPT 式聊天界面——说话时能显示图片/视频/网页这类多媒体,
像浏览器一样,因为涉及结果呈现与交互。

## 定位:这不是新东西,是三条已有线的汇合点

| 已有件 | 它贡献什么 |
|---|---|
| 单一接口宪法(语音拓扑裁定:一条线接协调者) | 这个界面=那条线的**可视化身**;user 仍只对协调者 |
| 可解释性产物(S16:HTML 页/MP4/交互图,全部已能产) | 聊天流里的**富媒体卡片**——产物本来就是网页态,嵌入即显 |
| S19 审批代理(弹窗→协调者箱→三门呈批) | 呈批卡=界面上**可点的交互**(批/驳/改),替代终端文字回执 |

一句话:**后端全部存在,缺的只是一块玻璃**。对话记录=我的耐久箱+发出消息(本就落盘);
富媒体=可解释性产物的文件路径;交互=写回收件箱的结构化回执。

## 形态(ponytail 阶梯裁剪)

- **v1=本地单页 Web 应用**(viz 轨同款栈,零新依赖):左侧对话流(语音转写+文字输入双模),
  卡片内嵌 HTML 产物 iframe/视频/图;右侧常驻看板(现有 kanban 复用)。本地 serve,不上云。
- 语音=CPA 实时模型接入这个页面(浏览器拿麦克风,比 CLI 插件省掉音频层的脏活——
  opencode-gpt-live 的回声消除/压低他应用都是 CLI 困境的补丁,浏览器原生就有)。
- 交互卡三类起步:呈批卡(S19 三门,批/驳按钮+理由框)/产物卡(页/片/图,点开全屏)/
  进度卡(多流状态,Dot demo 的「三线交错」可视化)。
- **集群状态视图=既有 swarm-viz 整合进同一前端(user 裁定 2026-10-05)**:kanban 三列+泳道/
  worklog 时间线/board 视图(swarm-viz.html,90b58f9c 作)不重写,作为控制台的「集群」标签页/
  常驻右栏嵌入——同一块玻璃看对话与全集群状态。整合形态由适配 owner 与 viz 作者对接缝
  (iframe 直嵌=零改动起步;数据源同机文件,无跨域问题)。
- **不做**:账号体系/多用户/云部署/移动端——一人公司,一块屏,本地起。

## 与装机门关系
门后批次,与 approval-delegation+语音面同批(三者本是一体:审批管线给卡片内容,
语音给输入输出,控制台给玻璃)。fitProfile=90b58f9c(viz 全链履历)。

## 命名
coordinator-console(协调者控制台)。它不是「聊天应用」——是蜂群的驾驶舱:
对话是操作方式,看板是仪表,呈批卡是方向盘上的确认钮。
