## 三个特命题（审查核心）

### ① 协调者单点：先炸上下文，后炸串行化

DHH 的 Amabot 是单点，但 DHH 本人=终审，**人类上下文+品味无界**。我们协调者=**有界窗口的 agent**。先炸点是**上下文**，不是串行化：
- 协调者独持全局（PROGRESS 裁定簿+在飞工单态+三类决策包），事件为 user 压缩、**无人为协调者压缩**——这是唯一「必须持全局态却窗口有界」的节点。
- 爆法：裁定簿+在飞态超一窗→compaction→细粒度裁定史丢失→**同一问题跨 compaction 答得不一致**。S29「先查三源」已在拉紧，但 PROGRESS 是散文、召回有损，正是前兆。
- 后炸点=串行化：所有升级路径汇到一个协调者，多成员同时 block⇒串行排空，block 延迟=队深×每件推理时；等同轴②「人空等=无用」搬到控制层。
- 修法：先给**结构化可查裁定簿**（治上下文，P2）；成员数真撞墙再上 R18 子协调者（judgment 分层，每层必**压缩**非转述——R21 已禁经协调者转述，方向对）。

### ② 审查席位：今日两席已排队，「随规模扩」实践未接

「审查人是 agent=随规模扩」的领先**只设计成立**。实况：两 codex 席轮转已排队，与 DHH 用资深**人**审=同一瓶颈，只是把人换成 agent。
- 为何只两席：对抗独立性(R21)要求跨家族审（claude 作→codex 审），故席位供给受 codex 席开设约束，不受「agent 可扩」自动满足。
- 叠乘：整件送审(S27)=每审吃大块审查上下文；N 件并行×多轮对抗×大上下文⇒席位快饱和；跨件架构审（轴⑤ P1）再加一类新席需求。
- 不可压的本质：审查**不可自审**，成本不可降地 O（N 件），无法像成员事件那样压缩。
- 修法：(a)审查席经容量管理器**按审查队深自动扩容**（让「随规模扩」实践成真，P2，依赖 T3 容量器）;(b)跨件架构审走**周期批**非逐件（避免叠乘席需）;(c)小疵/文档 S27 已自清，仅代码残留吃整席。

### ③ user 判断带宽：日预算小，呈批压缩率≈1x，且无仪表

CORE 北极星：user 只做三件（给目标/看观测/裁三类）,user 时间=公司唯一不可再生资源。user 多数离线⇒**日三类决策预算小**（每日个位数）。
- 压缩机制已有：代理权（可撤的协调者代行）+晨间追认单。但现**呈批逐条**（压缩率≈1x）,DHH 轴③要的是**一屏 N 件**（他「100 PR/90min 批量 merge」≈10x+）。
- 缺口=机制在码、不在手：decision-batch（事件→决策压缩）已建但休眠未接 console；晨间追认单也是散文、非一屏批动作。
- 最诚实的一条：**我们根本不测 user 决策数**。CORE 说「数外部激活」却无计数器——判断带宽是有原则、无仪表的量，今天在盲优化。
- 修法：先**装仪表**（日三类呈批+追认计数），再接 decision-batch→console 一屏批动作(P1)。这是直打终极瓶颈的单项最高杠杆。

## Top-5 薄弱环节修法清单（按对终极瓶颈的杠杆排）

1. **接 decision-batch→协调者控制台一屏批量动作视图**(P1)。90% 在码（b242d34 休眠），欠一块玻璃；直压 user 决策负载。杠杆最高、新建最少（接线）。服务命题③+DHH P1①②。
2. **给两条隐性带宽装仪表**(P1):user 日三类决策计数（CORE 已命名「外部激活」却从未建）+协调者上下文压力/审查队深。盲优化终极瓶颈=最大方法论缺陷。服务命题①②③。
3. **跨件架构整体性审查维度**(P1)：今对抗审仅逐件正确性，「各自合理、合起来碎」（轴⑤⑥）无归属；走**周期批**（非逐件，避免叠乘席需②）。本单即首个实例。
4. **结构化可查裁定簿**(P2)：以结构化账替 PROGRESS 散文裁定史，治协调者 compaction 后裁定不一致（命题①先炸点）；支撑 S29「先查三源」。
5. **审查席经容量管理器按队深自动扩容**(P2)：让「审查人=agent=随规模扩」实践成真而非仅原则（命题②）；依赖 T3 容量器先落。
