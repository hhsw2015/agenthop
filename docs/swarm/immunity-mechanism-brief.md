# 免疫机制设计简报:让「踩过的坑不再踩」成为流程环节,而非协调者的手艺

日期:2026-10-04。状态:**设计简报**(R4:重大机制,先设计后实施;走 design 节点→对抗审查→owner 实现)。
触发:F21 复盘后 user 三连定调——递归改进是核心环节/重复踩坑是最大时间成本/必须在流程机制上保证。反面教材即本简报的直接起因:协调者试图手写回归测试进实现方 worktree(越单编辑者边界,已撤回)——「user 指一下、协调者修一下」正是要被本机制取代的反模式。

## 要解决的问题(一句话)

F 系列(dogfood 免疫记忆)的「机制归宿」一步,目前靠协调者读文档、记得、手工落实——这条回路里的每一环(读/记/落)都是人,断任何一环,同一个坑第二次出现。

## 设计方向(利用已冻结机制,不发明新轨道)

冻结契约里已有全部零件,缺的只是接线:
1. **F 条目 → meta-job**(§0b R2 第 3 条「元工作入任务系统,不另设台账」,已冻结):每条 F 的四步处置里,「机制归宿」一步必须产出一个 meta-job 进任务系统(稳定来源标识=F 编号,天然去重),而不是一行「归宿:XXX 批」的文字。没有对应 meta-job 的 F 条目 = 处置未完成——这个检查本身可做进 dogfood 条目模板或 loadPlan 级校验。
2. **meta-job 的三级交付已冻结**:「实施并验证改进」级必须用**原反例**验证——即每个 F 的回归测试天然是其 meta-job 的验收标准,归**文件 owner** 在自己的测试域实现(1cfa162 批就是先例:R2 反例由纯层 owner 钉),不是协调者代写。
3. **「同编号 F 复发=最高优先级事故」的机械化**:F 回归测试进各 owner 的默认套件后,复发=测试变红=CI/review 门挡住——检测跑在代码里。对无法代码化的 F(流程类,如 F8 裁定-勘误解耦),归宿是 review-packet 模板的检查项(审查方执行,也是流程不是记忆)。
4. **协调者的角色收缩**:只做 F 条目的记录与 meta-job 的派发(这是调度),不做机制的实现(那是 owner 的活)。

## 待设计细节(design 节点的工作量)

- meta-job 的 spec 形状(acceptance = 原反例回归)与 F 编号的稳定映射;
- 「F 条目必须挂 meta-job」的校验位置(模板约定 vs loadPlan 机械校验)与豁免通道(纯叙事类 F);
- 既有 21 条 F 的存量清理:哪些已有等效回归(F17→liveness 测试族)、哪些缺、补欠单;
- 与欠条清单的关系(欠条=有触发条件的 meta-job?统一还是并行)。

## 验收(北极星对账)

机制落地后:user 指出一个新坑 → 协调者四步处置(分钟级)→ meta-job 自动排队 → owner 实现回归 → 审查收口——全程 user 只说了第一句话。「user 指一下」从触发人肉补丁,变成触发一条流水线。
