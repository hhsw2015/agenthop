## 原则

0. **时间是最大成本(user 定调 2026-10-04,F21 复盘后):空等是集群最贵的开销,优先级高于模型费用。** 一个节点空等 = 烧掉它的全部产能;全集群静待一个信号 = 烧掉整个组织(F21 实测:一个蒸发的 0/0 让集群静止 40 分钟——那 40 分钟里每个 idle 会话的机会成本,远超任何一次模型调用)。推论:① 调度优化的第一目标是**消灭无效等待**(wait 有 deadline、完成必有耐久信号、sweep 兜底推进),模型费用优化排其后;② 「贵模型一次做对」同时是时间优化——返工烧的首先是全链的墙钟;③ 账本(CPA)除了 modelUsd 必须记 **wallClock 与空等时长**(wait 的 open→resolved 区间、节点 idle 区间),「哪里在空等」要和「哪里在烧钱」同屏可见;④ 并行(R6)的本质就是时间成本优化——串行化=让后面的活空等前面的。

1. **返工是最大成本项(user 二次定调):分级的默认偏置是「宁贵勿返」**。便宜模型漏洞多来回修 ⇒ 总成本反升;贵模型一次做周全 ⇒ 反而省。全链成本 = 模型调用 + 重试 × (实现+审查+复验+协调) ——返工一次烧的是整条验收链,不只是那次调用。所以:难度存疑时**向上取档**;降档要靠账本数据证明「该类任务便宜档的一次通过率足够高」才降,升档不需要证明。本项目自身就是证据:R4「设计期多烧讨论买返工概率坍缩」与此同构——brain 契约三轮审查全发生在零实现时,每条反例的修复是改一段文字而非改模块+重测+重审。
2. **成本错配的定义是双向的**:贵模型干简单活 = 烧钱;便宜模型干难活 = 返工(重试+重审的代价往往超过一开始就用贵模型)。优化目标是「单位验收通过的成本」最小,不是单次调用最便宜。
3. **方向性工作钉死最高档(user 三次定调):kind 决定 tier 下限,难度只能往上调**。设计/计划/裁定(R4 的 kind:design 节点、计划修订、契约勘误、验收裁决)**必须**用最高档模型——方向错一毫米,下游执行全是返工,这正是「宁贵勿返」的极端情形:方向层的返工系数是全 DAG。执行层可低一档起步。于是 tier 规则是两段式:**kind 定下限**(design/review 类=heavy 恒定,不随难度降档),**难度在下限之上调节**(执行节点按 spec 标注的难易升档)。与现实公司同构:高层定方向用最强的人,执行分层配置。
4. **难度是 spec 的属性,放进 plan,不是调度时猜**。TaskSpec/plan 节点增 modelTier 提示(如 light/standard/heavy)由规划器(R4 design 节点的产出)标注;调度器只执行映射,不自己判难度——判断难度本身需要智能,属于规划期一次性成本,不该每次派发重复烧。
5. **验收是模型无关的**。两层验收不因便宜模型放宽:便宜模型产出照样过 V1-V8 + 对抗审查。模型分级只改「谁来干」,不改「什么算干完」——这是防止降级变成质量滑坡的闸。
6. **失败升级路径**:便宜模型连续失败(接 A2 失败指纹:同指纹 2 次)⇒ 升档重试(light→standard→heavy),升档记入 attempt 历史(投影可见「为什么这单最后用了贵模型」)。这给了「宁可先试便宜的」一个有界兜底。
7. **账本先行**:没有每 attempt 的真实 costUsd(CPA 账本/tasklog costUsd 字段,projection-schema §9 已留位),分级就只是感觉。先接账本看清各 tier 实际成本分布,再定映射——数据驱动,不拍脑袋。
